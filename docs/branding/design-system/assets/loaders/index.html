Two canonical loading animations for FilterEngineZ. Both square-format SVG + CSS, GPU-only animations, respect prefers-reduced-motion. Each has a different purpose — pick by what the loader needs to say, not by visual preference.

A SYNAPTIC ORBIT
AMBIENT · CALM · 11s ORBIT

Use for: ambient loading where the user is waiting passively — initial page load, idle background activity, "warming up the engine," route transitions. Reads as alive but considered.

Don't use for: short blocking spinners (<2s) — the rhythm doesn't have time to read. Use a hairline progress bar or stylized cursor flicker instead.

Use for: active computation that the user triggered — query running, filter rebuild, recomputation, "processing your data." Reads as the engine is firing — work is happening.

INTEGRATION

Both loaders are self-contained SVGs with CSS-only animation — no JavaScript needed at runtime. Copy the template from the source of this page (search tpl-a-orbit / tpl-b-cluster), copy the matching @keyframes + class rules, and you're set.

  • SVG viewBox: always 0 0 200 200. Set width + height on the <svg> element to render at any size.
  • Color tokens: the loaders read --loader, --loader-glow, --loader-deep, --loader-burnt, --loader-line, --loader-node. Define those on your root. Acid and phosphor are the two canonical themes — see the body class definitions above.
  • Reduced motion: a single @media (prefers-reduced-motion: reduce) rule kills all animation. Both loaders degrade gracefully — the node-glow + core stay lit so the visual is still recognizable.
  • Performance: GPU-only transforms (transform, opacity, filter). Tested under 4% CPU on a mid-range laptop at 192px.
  • Minimum size: 32px. Below that the synapse flickers and node fires don't have room to read; the orbital rings on A merge.
